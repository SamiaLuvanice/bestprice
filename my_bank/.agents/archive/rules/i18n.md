# Regra: i18n (pt-BR, en, es)

Detalhe e casos difíceis: skill `i18n`. Decisão de idiomas suportados: ADR em `docs/adr/`.

## Idiomas

| Código | Uso |
|--------|-----|
| `pt-BR` | Padrão, source of truth |
| `en` | Inglês (`Intl`: `en-US`) |
| `es` | Espanhol latino-americano (`Intl`: `es-419`) |

Não adicionar outros códigos sem tarefa `S-*` e catálogo completo.

## Obrigatório

1. **Paths de API e `error_code` em inglês.** `mensagem` (API) e labels (FE) saem do catálogo do locale ativo.
2. **Depois de S-05:** nenhuma string visível hardcoded em page, component, toast ou `AppException`. Chave nova nos **três** JSON (`pt-BR`, `en`, `es`) no mesmo PR.
3. **Antes de S-05:** UI em PT-BR literal é aceita; **proibido** misturar inglês/espanhol na mesma superfície ou inventar `if (lang === …)` fora da infra de i18n.
4. **Fallback `pt-BR`** se a chave faltar — nunca mostrar a chave crua (`auth.login.submit`) para o usuário.
5. **Datetime e dinheiro** usam o locale da UI (regra `datetime-pipeline`). Não hardcodar `"pt-BR"` em `toLocaleString`; usar as funções canônicas.
6. **Não traduzir** nome próprio: pessoa, cidade, empresa, marca.
7. **Sem locale na URL** (`/login`, não `/en/login`).
